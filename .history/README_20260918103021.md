# TinyLink API

A simple, secure, and efficient **URL Shortener REST API** built with **Laravel**.

TinyLink allows users to:

* Create short URLs from long URLs
* Use custom short codes
* Track URL click counts
* Manage their own URLs
* Authenticate securely using Laravel Sanctum
* Access protected REST API endpoints
* Redirect users from short URLs to their original URLs

## 🚀 Project Setup

### 1. Clone the Repository

```bash
git clone https://github.com/CoderShanto/tinylink-api.git
cd tinylink-api
```

### 2. Install PHP Dependencies

```bash
composer install
```

### 3. Configure Environment

Copy the example environment file:

```bash
cp .env.example .env
```

Generate the Laravel application key:

```bash
php artisan key:generate
```

Open the `.env` file and configure your database credentials:

```env
DB_DATABASE=your_database
DB_USERNAME=your_username
DB_PASSWORD=your_password
```

### 4. Run Migrations and Seeders

```bash
php artisan migrate --seed
```

This will:

* Create the required database tables
* Create users
* Create sample URLs
* Create the required Laravel Sanctum token table

The database seeder provides sample accounts for testing authorization.

### 5. Start the Development Server

```bash
php artisan serve
```

The API will be available at:

```text
http://127.0.0.1:8000
```

TinyLink uses **Laravel Sanctum** for token-based authentication.

Protected endpoints require an access token in the request header:


# 📡 API Endpoints

## Authentication

| Method | Endpoint        | Description                               | Auth Required |
| ------ | --------------- | ----------------------------------------- | ------------- |
| `POST` | `/api/register` | Register a new user                       | No            |
| `POST` | `/api/login`    | Login and receive an authentication token | No            |
| `POST` | `/api/logout`   | Logout and revoke the current token       | Yes           |
| `GET`  | `/api/me`       | Get the currently authenticated user      | Yes           |

---

## URL Management

| Method   | Endpoint         | Description                        | Auth Required |
| -------- | ---------------- | ---------------------------------- | ------------- |
| `POST`   | `/api/urls`      | Create a short URL                 | Yes           |
| `GET`    | `/api/urls`      | List the authenticated user's URLs | Yes           |
| `GET`    | `/api/urls/{id}` | Get details of a specific URL      | Yes           |
| `DELETE` | `/api/urls/{id}` | Delete a specific URL              | Yes           |

### Pagination

The URL listing endpoint supports pagination:

```http
GET /api/urls?page=1&per_page=10
```

---

## Public URL Redirect

| Method | Endpoint        | Description                                                | Auth Required |
| ------ | --------------- | ---------------------------------------------------------- | ------------- |
| `GET`  | `/{short_code}` | Redirect to the original URL and increment the click count | No            |

# 📝 Example Requests & Responses

## 1. Create a Short URL

### Request

```http
POST /api/urls
```

### Headers

```http
Authorization: Bearer {your_token}
Content-Type: application/json
```

### Body

```json
{
    "url": "https://www.example.com/very-long-url-here",
    "custom_code": "my-link"
}
```

### Response

**201 Created**

```json
{
    "success": true,
    "message": "URL shortened successfully",
    "data": {
        "id": 1,
        "user_id": 1,
        "original_url": "https://www.example.com/very-long-url-here",
        "short_code": "my-link",
        "click_count": 0,
        "created_at": "2023-10-25T10:00:00.000000Z",
        "updated_at": "2023-10-25T10:00:00.000000Z"
    }
}
```

---

## 2. List URLs with Pagination

### Request

```http
GET /api/urls?page=1&per_page=10
```

### Headers

```http
Authorization: Bearer {your_token}
```

### Response

**200 OK**

```json
{
    "success": true,
    "message": "URLs retrieved successfully",
    "data": {
        "current_page": 1,
        "data": [],
        "first_page_url": "http://127.0.0.1:8000/api/urls?page=1",
        "last_page": 1,
        "per_page": 10,
        "total": 2
    }
}
```

---

## 3. Public URL Redirect

### Request

```http
GET /my-link
```

### Behavior

When a user accesses a short URL:

1. TinyLink searches for the URL using the `short_code`.
2. The URL's `click_count` is incremented by `1`.
3. The user is redirected to the original URL.

For example:

```text
http://127.0.0.1:8000/my-link
```

redirects to:

```text
https://www.example.com/very-long-url-here
```

# 🛡️ Authorization & Security

TinyLink implements several security mechanisms to protect user data and API resources.

### Laravel Policies

Laravel Policies are used to ensure users can only access and manage URLs that belong to them.

For example:

* User A can view their own URLs.
* User A can delete their own URLs.
* User A cannot access User B's URLs.
* User A cannot delete User B's URLs.

Unauthorized access attempts return:

```http
403 Forbidden
```

### Request Validation

Incoming request data is validated using **Laravel Form Request classes** to maintain data integrity and prevent invalid input.

### Password Hashing

User passwords are securely hashed using Laravel's built-in `Hash` functionality.

### Token Authentication

Protected API endpoints use **Laravel Sanctum** authentication with Bearer tokens.
